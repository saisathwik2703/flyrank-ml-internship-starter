Content Refresh Opportunity Scoring: A Decision-Support Approach for Prioritizing Content Review

Cholleti Saisathwik

Abstract

This study asks which existing content items should be reviewed first for refresh, expansion, protection, pruning, or monitoring. The analysis uses the public-safe anonymized starter dataset supplied for the FlyRank ML Internship, with one row representing a pseudonymized content item and trailing 90-day performance signals. Logistic Regression, Decision Tree, and Random Forest models are compared with a transparent rule-based baseline using a client-aware holdout when available and the same test split for comparison. In the documented starter results, the Random Forest produced a ROC-AUC of 0.750, average precision of 0.618, and Precision@50 of 0.740, compared with baseline ROC-AUC 0.627, average precision 0.468, and Precision@50 0.240. The resulting score is intended to order items for human review and decision support, not to guarantee that a refresh will improve future performance.

1. Introduction / Problem

Content teams may have many existing pages and limited review capacity. The practical question is how to turn observed performance, freshness, visibility, and content attributes into a review queue that can be inspected by people.

The ML task is classification plus ranking. The target is is_declining_label, a proxy derived from the observed trend direction. The output is a model probability and combined ranking score used to prioritize review.

2. Data

The starter dataset contains 30,000 anonymized rows and 44 source columns. Each row represents a pseudonymized content item with trailing-90-day metrics. The public-safe workflow filters to items with impressions and sufficient content age, and deduplicates by content ID.

Identifiers are used only for grouping, joining, and client-aware validation; they are not model features. Trend fields used to construct the target are excluded from the feature matrix to reduce leakage risk. Rate fields are interpreted using the dataset's documented percentage convention.

3. Methodology

The analysis compares Logistic Regression, a constrained Decision Tree, and a Random Forest against a transparent baseline. The feature set contains numeric performance, freshness, content, and search-related fields plus selected categorical attributes. Numeric and categorical features are prepared consistently, while the target is kept separate from trend-derived leakage fields.

Where possible, validation holds out clients so that content from the same client is not split across train and test. If the available slice cannot support that split, the workflow falls back to a stratified row split. Model comparison uses the same test split and reports Precision@20, Precision@50, Precision@100, ROC-AUC, and average precision.

5. Limitations & Honest Framing

  • The target is a proxy for observed decline, not future refresh success.
  • The analysis is predictive and does not establish that a recommended action causes improvement.
  • The starter slice is not the full production warehouse and may not represent every content situation.
  • Seasonality, time-window changes, and future search behavior can change the observed signals.
  • Human review remains necessary before any content change or removal.
  • A high score means higher priority for review under this workflow; it is not a guarantee of outcome.

6. Ranked Recommendations

The final queue combines the selected model probability with the normalized transparent baseline score. The queue is a review order rather than an automatic action list.

  1. Review high-confidence items with strong model decline risk and meaningful visibility.
  2. Inspect visible pages with low click-through signals for possible title, snippet, intent, or positioning issues.
  3. Review pages with weak engagement or scroll signals for content-depth and user-experience issues.
  4. Inspect stale pages with continued visibility before deciding whether to refresh, expand, protect, prune, or monitor.

These recommendations should be checked against the actual page, intent, business context, and current performance before action.

7. Artifacts

The repository contains the capstone notebook, model comparison outputs, evaluation outputs, and generated charts used by the analysis. The notebook is the reproducible source for the analysis workflow.

8. Reproducibility

Run the notebook at work/notebooks/capstone.ipynb from the repository root. The notebook uses the repository's feature-preparation, baseline, training, and evaluation scripts and writes analysis artifacts under outputs/.

The model workflow uses fixed random seeds where applicable and documents the target, leakage checks, validation approach, and metrics in the notebook.
